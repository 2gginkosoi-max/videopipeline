# Веб-интерфейс «ГУСЬ ПЕРЕВОДИЛА»

Лёгкая обёртка над существующим конвейером. Логика сборки ролика **не переписана** —
веб-приложение только запускает `auto_news.py` как subprocess и транслирует его
вывод в браузер через WebSocket.

## Что умеет

- **Поиск новости в Reddit** — RSS-выдача без авторизации, пагинация, выбор
  источника (свой b-roll / ссылка на видео) и кнопка «сценарий по новости».
- **Сценарий** — вручную, из сохранённых в профиле, или сгенерированный LLM
  (Pollinations, бесплатно, без ключа) в трёх вариантах.
- **Голос** — встроенные референсы (мужские/женские, определяются по F0) либо
  **клон любого голоса**: загрузили файл → сервер сам нарезает речевой кусок
  (Whisper по таймкодам, а не «самый громкий», чтобы в b-roll с музыкой не
  попала музыка), распознаёт текст, определяет пол.
- **Профили** — регистрация/вход, у каждого свои ролики, голоса и сценарии.
- **Живой лог** конвейера в отдельной панели, прогресс по WebSocket, UI не
  подвисает: сборка идёт в фоне, конвейер сериализован (одна задача за раз).
- **Архив** готовых роликов с открытием папки в проводнике.

## Запуск

### Windows (как обычно)

```cmd
start_web.bat
```

или вручную:

```cmd
D:\AI\python310\python.exe D:\AI\VIDEO_PIPELINE\web\app.py
```

Открыть: <http://127.0.0.1:8000>

### Из свежего клона GitHub в любом каталоге

Пути к пайплайну и F5-TTS задаются в `web/config.py`. По умолчанию берутся
исторические `D:\AI\VIDEO_PIPELINE` и `D:\AI\F5-TTS`; если таких каталогов нет
(клон в другом месте, Linux, Docker), используются пути относительно репозитория.
Переопределить можно переменными окружения:

| Переменная | Что задаёт | По умолчанию |
|---|---|---|
| `VIDEO_PIPELINE_DIR` | корень пайплайна (`auto_news.py`, `output/`) | `D:\AI\VIDEO_PIPELINE` → корень репозитория |
| `F5TTS_DIR` (или `F5_TTS_DIR`) | каталог F5-TTS (`say_f5.py`, `stt.py`, `models/`) | `D:\AI\F5-TTS` → `<репозиторий>/F5-TTS` |
| `PIPELINE_PYTHON` | python для сабпроцессов конвейера | `D:\AI\python310\python.exe` → текущий python |
| `FFMPEG_PATH` | путь к ffmpeg | локальный путь → `ffmpeg` из `PATH` |
| `HOST` / `PORT` | адрес и порт `python web/app.py` | `127.0.0.1` / `8000` |

```bash
git clone https://github.com/2gginkosoi-max/videopipeline.git
cd videopipeline
python -m pip install -r requirements.txt
python web/app.py
```

Либо через uvicorn (так же, как в Dockerfile):

```bash
python -m uvicorn web.app:app --host 127.0.0.1 --port 8000
```

### Docker / HuggingFace Spaces

```bash
docker build -t goose-pipeline .
docker run --rm -p 8000:7860 goose-pipeline
```

Образ уже содержит ffmpeg; модели F5-TTS в него не входят — их нужно
примонтировать в `/app/F5-TTS` и указать `F5TTS_DIR=/app/F5-TTS`.
Для Spaces используется `README_HF.md` (SDK: docker, порт 7860).

### Нарезка
| Метод | Путь | Назначение |
|-------|------|------------|
| POST | `/api/slicing/start` | нарезать видео: файл (`video_file` или `videoFile`) либо `youtubeUrl`; возвращает `job_id` |
| GET | `/api/jobs/{id}` | статус (`processing`/`completed`/`failed`), `progress`, `clips[]`, `error` |
| GET | `/api/slicing/clip/{job_id}/{name}` | отдать нарезанный клип (только владельцу) |

Клипы режутся по 45 с (короткий хвост < 15 с приклеивается к предыдущему клипу)
и сохраняются в `web/users/<id>/videos/`.

Формат по умолчанию — вертикаль **1080×1920**:

- фон — кадр, растянутый по заполнению и размытый;
- основное видео — по центру с сохранением пропорций;
- вебка — если в кадре найдено лицо в углу (OpenCV Haar), область вырезается,
  в основном кадре замазывается и ставится сверху или снизу с рамкой;
- субтитры — faster-whisper распознаёт речь один раз на всё видео, затем для
  каждого клипа собирается ASS выбранным стилем (`classic`, `clean`, `neon`,
  `min`, `cinema`) и прожигается через libass.

Параметры формы: `vertical` (1/0), `subs` (1/0), `webcam` (`auto`/`top`/`bottom`/`off`),
`sub_style`. Кадры перекодируются (`libx264`, `veryfast`, `crf 23`), чтобы
границы были точными; `SLICE_MODE=copy` — быстрое копирование без перекодирования
(не работает вместе с вертикалью и субтитрами).

Переменные окружения для субтитров: `WHISPER_MODEL` (по умолчанию `small`),
`WHISPER_MODEL_DIR` (готовая папка модели), `WHISPER_DEVICE` (`cpu`/`cuda`,
по умолчанию определяется), `WHISPER_COMPUTE` (`int8`/`float16`), `WHISPER_LANG`
(например `ru`), `SUB_FONTS_DIR` (папка со шрифтом, если Montserrat не установлен).

#### Если YouTube просит «Sign in to confirm you're not a bot»

yt-dlp без cookies часто упирается в bot-check. Порядок действий:

1. Обновить yt-dlp: `python -m pip install -U yt-dlp`.
2. Передать cookies браузера: перед запуском `set YTDLP_COOKIES_FROM_BROWSER=chrome`
   (или `edge`, `firefox`). Если переменная не задана, сервер сам попробует
   chrome → edge → firefox **только после** bot-check (отключить:
   `YTDLP_NO_BROWSER_COOKIES=1`).
3. Либо файл cookies в формате Netscape: `set YTDLP_COOKIES=D:\cookies.txt`.
4. Проще всего: скачать видео вручную и загрузить его файлом — нарезка из
   файла не зависит от yt-dlp и работает всегда.

Каждая попытка скачивания пишется в правую панель лога, в тексте ошибки
приходит подсказка, а не сырой вывод yt-dlp с ANSI-кодами.

## Клонирование голоса: требования и проверки

F5-TTS копирует пару «аудио-референс + текст этого референса». Если текст не
совпадает с аудио, модель говорит неразборчиво. Поэтому:

- референс — 5–10 с чистой речи одного человека, без музыки, эха и шума;
- после нарезки референс транскрибируется **заново** и проверяется
  (3–12 с, минимум 4 слова) — текст гарантированно относится к этому файлу;
- в лог пишется `[VOICE] референс: 8.0 c, слов 19: ...`;
- если речи не слышно (тишина/музыка), клон не создаётся и возвращается
  понятная ошибка.

После генерации озвучки `auto_news.py` запускает `voice_check.py`: ASR по
`voiceover.wav` сравнивается со сценарием (покрытие ≥ 90%, хвост ≥ 60%).
Если F5 потерял конец длинного текста, сборка останавливается с объяснением,
а не отдаёт короткий ролик с «кашей» и кривыми субтитрами. Собрать как есть:
`set ALLOW_BAD_VOICE=1`.

## Настройки формы → флаги `auto_news.py`

| Поле формы        | Флаг            |
|-------------------|-----------------|
| Сценарий          | `--script-file` (файл пользователя) |
| Локальный путь    | `--asset`       |
| Ссылка b-roll     | `--video-url`   |
| Сегменты          | `--segments`    |
| Темп речи         | `--factor`      |
| Голос             | `--voice-ref` + `--voice-ref-text` |
| Приватность       | `--privacy`     |
| Категория         | `--category`    |
| Музыка            | `--bed`         |
| Позиция гуся      | `--goose-pos`   |
| Без гуся          | `--no-goose`    |
| Sharpen           | `--sharpen`     |
| Без озвучки       | `--skip-voice`  |
| Без загрузки      | `--skip-download` |
| Без публикации    | `--skip-publish` |
| Куда сохранить    | `--final` (папка пользователя) |

Сценарий пишется в `web/users/<uid>/scenario.txt` и передаётся через
`--script-file`: так не упёрться в лимит длины командной строки Windows
(8191 символ) и не затирать общий `D:\AI\F5-TTS\scenario.txt`.

## Ограничения Reddit

Анонимный RSS отдаёт 429 уже при ~1 запросе в 10 секунд. Поэтому поиск ходит
**строго последовательно** с паузой 12 с, экспоненциальным backoff и кэшем на
15 минут, максимум 3 сабреддита за запрос. Если часть сабреддитов не
ответила — показываются те, что ответили.

## Публикация

Перед публикацией `auto_news.py` сам вызывает `originality_check.py`.
Если проверка не пройдена — публикация блокируется, в лог пишется `[BLOCK]`.
Отдельно запускать проверку не нужно.

## Что нужно для публичного хостинга

Текущая версия — локальная: она пишет в `D:\AI\VIDEO_PIPELINE` и запускает
F5-TTS/FFmpeg на этой машине. Для публичного доступа «для всех бесплатно»
понадобится:

1. Отдельный сервер/VPS с GPU (F5-TTS идёт через CUDA, ~4–6 минут на ролик).
2. Очередь задач (Redis/RQ или Celery) вместо `asyncio.create_task`.
3. Файлы в S3-подобное хранилище, а не в локальную `output/`.
4. Авторизация и квоты, чтобы публичный сайт не сжёг GPU и YouTube-квоту.
5. Секреты (YouTube OAuth, VK token) — в переменные окружения, а не в файлы.

Правила оригинальности из `ORIGINALITY_GUIDE.md` при этом остаются в силе —
они внутри `auto_news.py` и меняться не должны.
